Teaching Android Notifications to Understand What Matters

How I deployed K2 Horizon 0.9B locally on an 8GB Android phone, fought thermals and battery drain, and discovered that Small Language Models make incredible Ahead-of-Time Rule Compilers.

01 The Real Problem: The "Do Not Disturb" Trap

We get bombarded with dozens—often hundreds—of notifications every single day. Between delivery updates, social media banter, group chats, promotional sale pings, and app nagging, the modern smartphone notification shade is pure noise.

When doing deep work or trying to focus, most of us resort to turning off notifications or flipping on Do Not Disturb (DND). But that workaround has a major flaw: you miss the things that actually matter.

The Flawed Status Quo: DND

Muting everything silences spam, but you miss critical missed calls, emergency work pings, urgent recruiter messages, or close friends organizing a cricket match.

The Goal: Contextual Edge Firewall

Define natural language rules once (e.g. "any msg from Arjun related to job is important") and let an air-gapped on-device AI intelligently triage every alert.

I wanted a 100% private, on-device notification analyzer for Android that could evaluate plain-English user rules. No cloud APIs, zero telemetry, full privacy. Enter K2 Horizon.

02 The Early Prototypes: Fighting Thermals & Battery Drain

I started experimenting on my daily driver: an 8GB RAM Android phone. The open-weights K2 Horizon 0.9B model caught my eye because of its compact parameter size and promising reasoning capability for small-footprint hardware.

Attempt 1: Unquantized 0.9B in Memory

My first setup loaded the unquantized 0.9B model (~2.1 GB) into memory. While it technically fit in the 8GB RAM headroom, the reality of running full-precision forward passes on an Android CPU was immediate: the phone turned into a pocket heater. Constant background processing triggered thermal throttling and slaughtered battery life.

Attempt 2: 4-bit Quantization (K2 Horizon 0.9B Q4_K_M)

To make notification triage practical, I quantized K2 Horizon 0.9B to 4-bit (Q4_K_M GGUF format, ~635 MB on HuggingFace). The memory footprint dropped dramatically from 2.1 GB to under 650 MB.

However, keeping the model continuously resident in RAM and sending every incoming notification to the LLM for JSON classification still created noticeable warmth during high-notification bursts (e.g. active group chats or multi-app pings).

Attempt 3: Lazy Loading with Idle Eviction

Next, I introduced a lazy-loading state machine with a 5-minute idle eviction timer. If no notifications arrived for 5 minutes, the engine cleanly freed native RAM. This helped idle battery consumption, but whenever a burst of notifications arrived, the device would repeatedly fire CPU cores for repetitive inferences.

03 The Architectural Breakthrough: Ahead-of-Time Rule Compilation

That's when the core insight hit me:

"Why should an LLM run at runtime on every single incoming notification just to check if Madhu sent a reel or if a message came from Teams?"

Users create or update rules rarely (once a week or month), but notifications arrive hundreds of times a day.

Instead of using K2 Horizon 0.9B as a slow runtime classifier for every notification, I redesigned the system to use K2 Horizon as an Ahead-of-Time (AOT) Intent Compiler at rule configuration time!

System Architecture: Hybrid AOT Dual-Engine Zero Runtime LLM Waste
Phase 1: Rule Creation (K2 AOT Compiler)

When the user types a rule in natural language, K2 Horizon parses the intent, extracts positive/negative topic anchors, sender targets, and classifies the execution engine:

{
  "rule_type": "CONDITIONAL_CONTACT",
  "execution_engine": "AOT_FAST",
  "target_person": "madhu",
  "excluded_topics": ["reels", "reel", "video"]
}
Phase 2: Runtime Triage (<0.2ms vs On-Demand)
  • ⚡ Fast Path: Deterministic rules (<0.2ms) evaluated purely in Kotlin with zero CPU spikes.
  • 🧠 K2 Deep AI: Only subjective/emotional rules (e.g. anger detection) wake up the quantized model on demand.

With this hybrid architecture, over 90% of incoming notifications bypass the LLM completely, executing in under 0.2 milliseconds. Thermals stayed cool, battery drain became virtually unmeasurable, and the phone remained responsive.

An Interesting Edge Case with 0.9B Quantization

In our live testing, when Pranav sent "I'm very displeased", the model evaluated it as formal dissatisfaction rather than explosive anger, allowing the broad contact rule to pass through. For a 4-bit 0.9B model, fine-grained semantic boundaries between mild displeasure and anger are an intriguing edge case. Overall, however, the system achieved over 95% accuracy in matching user intent across real notification streams.

05 What This Proves About Small Language Models

This experiment changed how I view sub-billion parameter models. Small models like K2 Horizon 0.9B don't need to be all-knowing chatbots. When applied intelligently:

  • They make phenomenal compilers: Translating ambiguous human rules into deterministic token-matcher schemas in one shot.
  • Hybrid architectures beat pure LLM loops: Offloading routine checks to deterministic code preserves battery while keeping AI precision on standby.
  • Privacy on the edge is genuinely viable: Completely offline notification intelligence without sending personal chats to cloud servers.
